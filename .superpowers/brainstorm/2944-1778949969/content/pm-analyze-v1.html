为什么你用不上这些功能？——产品经理视角

不是功能不好，是它们和你的月视图主战场脱节了

🔍 现状分析：功能孤岛

你的核心行为是月视图 → 新建任务。每个高级功能都存在一个共同问题：脱离主流程，需要你主动去另一个地方操作。

矩阵（四象限）

问题：在创建模态框底部选象限，月视图上看不到任何象限信息。分类了但看不见，等于没分。

项目

问题：要先在另一个模态框建项目，再在任务里关联。月视图上只能靠一个小色条区分。操作链太长，收益不明显。

周期规则

问题：独立的管理器，完全脱离创建流程。你建任务时不会想到「去周期管理器建规则」。触发点不存在。

标签 / 子任务 / 依赖

问题：全部藏在编辑模态框里，创建时不出现，月视图上也看不到。存在感为零。

日视图 / 列表视图

问题：切换后看不到月历的上下文，像是完全不同的应用。之间没有联动。

📊 同类产品怎么做？

Todoist — 自然语言即界面

核心哲学：输入框承担一切。用户不需要「学功能」，只需要打字。

买牛奶明天下午4点 #生活 p1

一行文字自动解析出：
标题「买牛奶」日期「明天」时间「下午4点」
项目「生活」优先级「p1」
→ 没有模态框，没有下拉菜单。

Things 3 — 日历即中心

核心哲学：所有内容最终汇聚到日历。项目、标签、截止日期都在日历语境下呈现。

- 侧边栏选项目 → 日历自动过滤
- 拖拽任务到日期 → 即时重排
- 项目进度在日历上可视
→ 日历是集成中心，不是孤立视图。

TickTick — 功能模块化但无缝切换

- 日历 + 列表 + 矩阵在底部 Tab 一键切
- 周期任务在创建时一个开关决定
- 番茄钟嵌入任务卡片
→ 功能多但不割裂，都在同一个任务卡片上操作。

Linear — 键盘驱动，视图即过滤器

- 矩阵/列表/日历只是同一批数据的不同视角
- 快捷键瞬间切换，不中断心流
- 创建时只问最少信息，后续在列表上快速补充
→ 创建和整理是两个独立的、各自优化的流程。

💡 核心结论

NextDo 的根本问题不是缺功能，是创建时问了太多，月视图上展示了太少

  • Todoist 模式：创建时用自然语言一句话搞定，不用填表单
  • Things 模式：月视图是核心，所有信息在日历上可见，不用切来切去
  • Linear 模式：创建和整理分离——创建要快，整理时才补充细节
